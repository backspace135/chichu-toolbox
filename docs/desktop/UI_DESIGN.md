## 2. 设计原则

1. **精致且开箱即用。** 使用成熟 Mantine 控件，少量业务样式建立产品风格，避免重新实现已有控件。
2. **状态先行。** 当前设备、连接模式和可用能力持续可见；操作结果来自真实执行与验证。
3. **桌面工作区。** 左侧导航、顶部设备上下文、中央表格或流程，任务详情按需展开。
4. **克制分组。** 浅灰工作区、清晰分组、有限蓝色强调、细边界；保留概览页的快捷工具与解锁入口层级。
5. **任务可追踪。** 页面切换不使任务记录消失，阶段、输出与最终结果分别展示。
6. **两端一致。** Windows、macOS 共用产品视觉；窗口、系统菜单与快捷键遵循宿主平台习惯。macOS 仅支持 Apple Silicon。

## 3. 组件与样式

| 层面 | 决定 |
| --- | --- |
| 框架 | Tauri 2 + React + TypeScript + Rust |
| 组件库 | Mantine，确认基准版本 9.8.0 |
| 标准控件 | Mantine Button、ActionIcon、Table、Checkbox、SegmentedControl、Menu、Modal、Drawer、TextInput、Progress、Switch、Tooltip 等 |
| 图标 | Tabler Icons，常规线性图标，笔画约 1.65px |
| 样式 | Mantine 主题和组件参数优先；业务布局使用 CSS Modules |
| 令牌管理 | 正式工程集中维护颜色、字号、形状及组件默认值，页面消费语义令牌 |
| 终端 | 正式实现沿用技术栈中确定的 xterm.js；mock 中的输入框仅演示会话布局 |

mock 的全局 CSS 是独立预览实现；正式工程沿用其视觉，不要求原样复制选择器、单文件组件结构或演示逻辑。高级数据表组件在应用管理实际实施时确定，外观与行为按本规范对齐。

### 4.2 字体与密度

- 中文跟随系统无衬线字体，macOS 优先 PingFang SC，Windows 优先 Microsoft YaHei；英文使用本机可用的 Inter 或系统字体，不要求在线字体。
- 常规桌面窗口：页面标题约 27px、设备名约 28px、分组标题 15px、主要列表文字 13–14px、摘要与说明 11–12px。
- 9–10px 仅用于次要元信息，不能承载错误、状态含义或主要操作说明。
- 终端使用 SFMono-Regular / Consolas 等系统等宽字体；数值使用等宽数字对齐。
- 用户缩放时允许换行和滚动，包名、路径和错误详情应可查看完整内容。

### 4.3 布局、形状与尺寸

| 项目 | 常规桌面基准 |
| --- | --- |
| 左侧栏 | 228px；较窄窗口收至 205px / 185px |
| 顶栏 | 68px，高度内包含面包屑、设备选择与辅助操作 |
| 主区水平边距 | 40px；随窗口缩小至 26px / 20px / 15px |
| 主内容最大宽度 | 1430px，居中 |
| 页面标题与内容间距 | 约 28px |
| 分组间距 | 18–22px；快捷工具间距 14px |
| 分组内边距 | 约 24–28px |
| 形状 | 分组使用 Mantine `lg` 圆角；按钮 `md`，导航约 8px 圆角 |
| 普通主按钮 | 约 35–36px 高；顶部图标按钮约 34px |
| 图标 | 常规 17–19px，快捷入口 23px |

保留细边界，普通分组不叠加明显阴影。浮层与短反馈可以有轻微阴影。首页设备插画作为辅助示意，不替代真实设备信息，也不暗示匹配到了具体机型外观。

## 5. 页面框架与导航

侧栏依次为 **设备概览 → 解锁 Bootloader → 应用管理 → 文件传输 → 终端与日志**，**设置**置于侧栏底部。顶部设备选择贯穿工作区；任务中心保持轻量入口，通过抽屉查看记录。

```text
┌ 产品与工具搜索 ┬ 面包屑              当前设备  主题  任务 ┐
│ 设备概览      │ 页面标题与说明                 主操作 │
│ 解锁 BL       │                                      │
│ 应用管理      │          表格 / 设备信息 / 分步流程   │
│ 文件传输      │                                      │
│ 终端与日志    │                                      │
│               │ 状态摘要                             │
│ 设置          ├ 任务中心                             ┤
└───────────────┴──────────────────────────────────────┘
```

### 响应式

- 约 980px 以下，复杂左右分栏改为上下排列，快捷工具由四列变为两列。
- 约 760px 以下，侧栏改为可展开导航，顶部保留设备选择与必要操作。
- 宽表格在自身容器内横向滚动，不能使整个窗口横向溢出。
- 窄窗口参考用于检查重排，不代表桌面客户端承诺任意最小窗口尺寸；实际 Tauri 最小窗口尺寸在工程初始化时确定。

## 6. 页面规格

### 6.1 设备概览

- 顶部设备组：连接状态、设备名、系统与代号、ADB 授权、Bootloader 状态；电量、温度和权限信息为次级摘要。
- 常用工具四个入口：安装应用、传输文件、屏幕截图、打开终端。
- 下方保留解锁主入口、设备信息分组与最近操作。
- 完整信息放入弹窗；日志与历史通过记录入口展开。
- 未连接时明确显示连接入口；读取中、拒绝授权、offline、读取失败各自显示真实状态。

### 6.2 解锁 Bootloader

- 采用「连接设备 → 检查适配 → 执行解锁 → 验证结果」的阶段布局。
- 主区域依次是阶段、当前设备、检查项、当前结果与主操作；右侧为简短流程说明和实际采用的方案信息。
- 未接入、不支持、待验证、检查中、执行中、失败与验证成功分别表达；不能把候选方案显示为已支持。
- 当前主操作随真实阶段变化，按键与插拔说明在需要时展示。取消是否可用由当前设备操作决定，不能伪造已停止或已回退。

### 6.3 应用管理

- 顶部搜索、全部 / 用户 / 系统 / 已冻结分段筛选，安装操作位于标题右侧。
- 连续表格展示选择框、应用图标与名称/包名、类型、占用空间、状态、更多操作。
- 多选后展示选择数量与批量操作；单应用详情放入弹窗，更多操作使用菜单。
- 读取失败、空列表、无搜索结果与服务不可用保持不同状态；操作结果以设备响应更新。

### 6.4 文件传输

- 主区用面包屑与文件表格浏览目录；辅助区用于选择文件与传输进度。
- 进度、方向、文件名和结果持续可查。真实文件选择使用系统选择器；实现拖放时提供同等按钮入口。
- 不可访问的目录显示具体原因，不能以空目录掩盖失败。

### 6.5 终端与日志

- 连续终端工作区，顶部提供 Shell / 任务日志切换及必要操作，底部显示会话状态。
- 正式终端使用真实设备会话，保留输入输出、尺寸变化和退出状态；切页不重建仍在运行的会话。
- 日志导出保存真实内容；预览中的预设响应不进入客户端。

### 6.6 设置

- 使用分组行组织外观、连接与记录偏好；关于信息在次级分组。
- 深浅色与紧凑模式沿用确认的布局和样式。
- 只提供已有实现的设置，开关状态对应真实存储与行为。

## 7. 交互与可访问性

- `⌘ + K`（macOS）/ `Ctrl + K`（Windows）打开工具搜索；快捷键提示跟随平台。
- 弹窗和抽屉打开后焦点进入，关闭后返回触发入口；普通可关闭浮层支持 Escape。
- 图标按钮有可访问名称、悬停说明和可见焦点；进度条有业务名称和真实进度。
- 短反馈用于告知完成，失败保留在操作区域或任务记录中，不能只显示即消失的提示。
- 长任务通过任务中心查看阶段与输出，不依赖页面停留维持任务；不支持确定百分比时使用阶段或不定进度。
- 主体文字对比度至少 4.5:1，适用的大字和非文字控件至少 3:1；深浅色均验证。
- 尊重系统减少动态效果设置，不添加持续装饰动画。

## 8. 实现与变更规则

- 修改桌面 UI 前先读本规范；Mantine 主题与共享组件集中维护，不在每页重做控件。
- 改变导航结构、主色体系、页面层级或主操作前，先更新规范和 mock，并获得用户确认。
- 普通排版修复、无障碍修复和真实状态补全按本规范实施；补充新能力时沿用既有分组和任务模式。
- 验证在 Windows WebView2、macOS Apple Silicon WKWebView 的正式 Tauri 窗口中分别进行，构建成功或浏览器 mock 检查不能代替桌面视觉验收。

### 实现验收要点

- [ ] 六页框架、分组层级、侧栏、顶部设备与任务入口对齐确认基准。
- [ ] 深浅色、紧凑模式、窗口重排和缩放可用，主要操作与信息可达。
- [ ] 无演示设备数据、预设输出、预览开关或模拟成功。
- [ ] 设备授权、断连、读取错误、空状态和任务失败准确显示。
- [ ] 表格搜索/筛选/多选、菜单、弹窗与抽屉的键盘和焦点行为正常。
- [ ] 长任务进度、输出、取消能力与结果对应真实执行。
- [ ] 两个目标平台分别记录构建、交互与视觉验证结果。
