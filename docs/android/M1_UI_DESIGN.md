# M1 界面设计

> 历史方案。2026-11-09 用户确认的新界面与后续实现要求以 [Android UI 规范](UI_DESIGN.md) 为准；本文保留 M1 当时的设计依据与业务状态约束。

## 目标与依据

围绕服务激活和 Shell 授权交付原生 Android 界面，统一三个上游的视觉语言，而不是把三个 App 的界面并排拼接。用户提供的 miuix 官方示例截图作为视觉参考；本文的页面组织与尺寸是实施建议，等待确认后编码。

技术约束沿用 [TECH_STACK.md](TECH_STACK.md)：Kotlin、Jetpack Compose、单 Activity、Compose Navigation、手写 AppContainer、minSdk 31。主要组件固定为 `top.yukonga.miuix.kmp` **0.9.4**；Material 3 提供必要的底层能力，不混用两套外观。

## 视觉系统

- 使用 `miuix-ui-android`、`miuix-preference-android`、`miuix-icons-android`；导航仍按既定方案使用 Compose Navigation，不因为上游使用 miuix-nav 就更换架构。
- 主题统一由 `ToolboxTheme` 提供；默认跟随系统明暗，蓝色主操作。设置提供跟随系统、浅色、深色和动态配色选项。
- 所有页面使用主题语义色，不将截图中的浅色值硬编码到深色主题。
- 页面水平最小边距 12dp，分组间距 12dp，卡片内边距以组件默认值为主；宽屏内容最大宽度 800dp。
- 圆角、字重、开关、按钮、输入框优先采用组件默认值，不仿造一套相似组件。
- 标题和说明遵循 miuix 字体层级；包名与激活命令允许换行，命令使用等宽字体、可选择和复制。
- 使用同一套 miuix 线性图标；状态始终有文字，不只靠颜色区分。
- 不引入大面积玻璃效果、装饰渐变、无意义动效或全屏终端风格。动效沿用组件默认行为，并兼容系统关闭动画。
- 交互目标至少 48dp，图标按钮提供中文无障碍描述，200% 字体下内容不截断。

## 页面与导航

M1 三个一级入口：**权限服务、应用授权、设置**。手机使用底部导航；窗口可用宽度达到 600dp 时使用侧边导航。不是照搬截图里的 Home/Icon/Color 组件展示菜单。

后续临时 Root 与 Root 管理保留模块边界，本里程碑不展示可点击的假功能。服务列表与 Root 授权列表不能合并成一种权限。

### 权限服务

从上至下：

1. 标题「权限服务」。
2. 服务状态卡：未激活、正在激活、已连接、连接已断开、激活失败。在线时显示 Shell 身份、服务版本；不把 Shell 身份显示成 Root。
3. 共存提示：分别表达「已安装原版」与「确认原版服务运行中」；无法确认运行状态时明确说明，不根据安装状态推断双服务。没有自动停止或接管原版的按钮行为。
4. 未激活时突出「无线调试激活」；电脑 ADB 为同等可达的替代入口。已连接时突出「管理应用授权」，激活方式作为次级入口保留。
5. 本机设备信息，收纳 Android 版本等辅助内容。

Binder 死亡立即清除在线信息与可执行状态，显示重新激活入口。恢复前台时重新校验，不沿用缓存的绿色状态。

### 无线调试

用明确步骤组织，不一次堆满系统权限申请：

1. 打开开发者选项中的无线调试，提供跳转设置和简明说明。
2. 发现配对端口，输入六位配对码；发现不到时提供手动端口输入。
3. 配对成功后发现连接端口并启动内置服务；明确区分配对端口与连接端口。
4. 只有收到且验证内置服务 Binder 后才显示成功，命令返回成功不代表连接成功。

配对码只在当前操作内存中使用，不写入日志或持久存储。错误保留在当前页面，说明下一步；输入错误可以重试。操作有取消、超时和防重复提交。需要通知权限时再申请；拒绝后说明受限能力或提供前台手动流程，不导致整个 App 无法使用。

### 电脑 ADB

展示根据当前安装路径生成的真实命令及复制按钮。APK 更新后重新生成，不固定 `/data/app/…` 路径。不再用旧版 `start.sh` 文案误导当前 native starter 的启动方式。

说明电脑授权调试、执行命令、回到 App 检查结果三个步骤。日志用底部弹层展示，并可复制经过敏感信息过滤的诊断内容。

### 应用授权

- 搜索框及原生应用列表：图标、应用名、包名、授权状态；同 UID 的共享授权关系明确提示。
- 状态至少区分未授权、已批准、已拒绝；撤销后不继续显示允许。
- 服务离线时展示不可管理的说明和激活入口，不伪装成「没有应用」。加载失败、空列表、没有搜索结果各用独立文案。
- 允许、拒绝、撤销通过内置服务管理接口完成；授权操作失败不得先把列表永久改成成功状态。
- 第三方权限请求以本 Activity 中的 Compose 确认界面承接，展示经服务端校验的真实应用身份，明确请求的是 **Shell 权限，不是 Root 权限**。
- 关闭、返回或取消确认界面按拒绝处理，不能悬挂请求或默认允许。外部伪造 Intent 不能触发授权。
- M1 必须支持批准和拒绝；本次建议不增加「仅本次」按钮，避免在服务生命周期尚未验证前扩大交互范围。

### 设置

使用 `Card` + `ArrowPreference` / `SwitchPreference` / 组件库选项控件的分组列表：

- 外观：主题与动态配色。
- 服务说明：Shell 与 Root 的区别、与原版 Shizuku 的共存提示。
- 关于：工具箱版本、固定的上游版本、许可证入口。

不放尚未实现的功能开关。首次启动只读取状态，不强制申请全部权限。

## 状态与实现边界

- 页面只消费不可变 `StateFlow`，操作经 ViewModel 进入 repository；AppContainer 统一装配依赖。
- `:core:common` 提供服务连接状态与授权领域模型，Shell 和未来 Root 使用独立类型。
- `:core:shizuku` 负责内置服务连接、授权、启动及无线调试；UI 不直接读写授权配置文件。
- 依赖 Binder 的读取与命令执行离开主线程，进程死亡和取消可中断操作。
- 纯状态变换做 JVM 单测；真实 Binder、配对、启动、第三方授权及共存做真机验收。

## 界面验收

- [ ] 窄屏与宽屏导航正确，不发生底部栏和侧栏重复显示。
- [ ] 浅色、深色、动态配色均无低对比的状态文案。
- [ ] 大字体、长应用名、长命令可阅读，内容不被系统栏或键盘遮住。
- [ ] 未激活、启动中、已连接、断线、失败、加载、空列表、无搜索结果都有真实状态。
- [ ] 激活失败可重试，取消不会随后误报成功。
- [ ] 应用授权与 Shell 状态没有任何 Root 已授权的误导文案。
- [ ] 服务断开立即更新 UI，恢复前台重新检测。
- [ ] 共存提示不把「安装了原版」等同于「原版服务正在运行」。
