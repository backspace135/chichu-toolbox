## 2. 设计原则

1. **状态先行。** 先说明当前连接与可用能力，再给出对应操作。
2. **每屏一个明确主操作。** 服务在线时管理授权，离线时无线激活；其他入口使用设置列表。
3. **分组而非卡片堆叠。** 相同职责的列表行合并到一个分组；应用授权使用一张连续列表。
4. **说明按需展开。** 激活步骤、日志、共存说明、完整系统信息放在弹层，首页只留必要摘要。
5. **原生、安静。** 系统中文字体、线性图标、有限的状态色；不使用装饰渐变、悬浮阴影或玻璃卡片。
6. **真实能力。** 已安装不等于运行中，Shell 不等于 Root，配置有效不等于设备受支持。

## 3. 设计令牌

按「基础值 → 语义角色 → 组件」使用令牌。Android 中统一在主题和共享组件定义，不在各页面分散写颜色、字号和圆角。标准控件优先使用 miuix；允许通过主题与控件参数匹配本规范。

| `surface` | `#FFFFFF` | `#232323` | 分组卡片 |

| `secondaryText` | `#777B83` | `#A4A4AA` | 辅助信息 |
| `sectionLabel` | `#7E879F` | `#A2A6B8` | 分组标题 |
| `primary` | `#3482FF` | `#65A1FF` | 主要操作与选中态 |
| `onPrimary` | `#FFFFFF` | `#071833` | 主按钮内容 |
| `primaryContainer` | `#EAF2FF` | `#21334F` | 筛选选中背景、设备图标背景 |
| `input` | `#EAEAEC` | `#2A2A2C` | 搜索框、次级按钮 |

动态配色开启时，主色及其容器使用系统语义色，不继续混用固定蓝。连接状态仍有明确图标和文字，不能只靠绿色表达。错误色使用主题错误语义色；拒绝授权和操作失败不能显示为连接成功色。

### 3.2 字体与单位

- Android 使用系统无衬线字体；有 MiSans 时跟随系统，不打包外部字体。
- Android 尺寸使用 dp，字号使用 sp。HTML 为缩小展示，不能将所有 9–12px 小字原样搬入客户端。
- 页面标题：30sp，中等字重；连接状态：25sp，半粗；设备型号：21sp，半粗。
- 列表主文：16sp；摘要、状态、包名和说明：12–14sp；分组标题：13sp、中等字重。
- 命令、完整内核版本、构建指纹与 SHA-256 使用等宽字体，可选择、换行。
- 状态、包名、错误信息不单行截断；应用长名称可换行。

### 3.3 间距与形状

| 组件令牌 | 基准 |
| --- | --- |
| 页面边距 | 12dp；标题起点 24dp |
| 内容最大宽度 | 800dp，居中 |
| 同组内容间距 | 8–12dp |
| 分组上间距 | 20–24dp；标题至分组 8–10dp |
| 分组圆角 | 20dp |
| 状态卡圆角 / 内边距 | 24dp / 20dp |
| 列表行内边距 | 水平 16dp，垂直 14–16dp |
| 列表图标 / 应用图标 | 24dp / 40–44dp |
| 行内图标与文字间距 | 12dp |
| 主按钮圆角 / 最小高度 | 14dp / 48dp |
| 搜索框圆角 / 最小高度 | 胶囊 / 48dp |
| 弹层顶部圆角 | 沿用 miuix BottomSheet |
| 所有可点击目标 | 至少 48dp；图标视觉尺寸不等于点击尺寸 |

普通分组不加外描边或阴影。细分隔线从正文起点对齐，非每一行都画完整边框。状态卡的大勾为非交互装饰，放右侧，不遮挡文字；放大字体时允许隐藏或降低存在感。

## 4. 导航与页面框架

固定四个一级入口，顺序为 **权限服务 → 应用授权 → 设备诊断 → 设置**。

- 手机：底部导航，单色线性图标，选中项使用正文色与更明显字重，不用蓝色胶囊背景。
- 可用宽度 ≥ 600dp：切换侧栏，不同时显示底部导航；主内容限宽 800dp。
- 顶部：小号产品名、右侧页面操作、大标题；列表在系统栏与导航之间独立滚动。
- 系统栏、IME、横屏和大字体使用实际安全区，不模拟 HTML 手机边框。
- 现有导航状态恢复、返回操作和权限请求入口继续有效。
- 页面切换采用有方向的水平滑动：前往底栏右侧入口时向左滚动，前往左侧入口时反向；返回回到「权限服务」。不叠加淡入淡出，不允许旧页闪现。使用 KernelSU / miuix 示例的 `HorizontalPager`、`horizontalPagerSwipeOverride` 与 `PagerNavigationSpringSpec`（stiffness 322.2、damping 约 0.90）：拖动实时跟手，新手势或点击从当前显示位置接管。`ToolboxPagerState` 在连续点击时保留当前速度，不重复重启同一目标，旧任务不得回写新目标；四页保留组合状态，避免跨页时反复加载；系统栏只随主题变化更新。松手和点击均非线性弹簧收尾，不固定 500ms。弹层沿用 miuix 的 `folmeSpring(0.9, 0.38)`。系统关闭动画时跟随系统。

## 5. 页面规格

### 5.1 权限服务

```text
产品名                              说明
权限服务

┌ 已连接状态卡 ──────────────────────┐
│ 内置权限服务                大勾  │
│ 已连接                            │
│ 服务运行正常                      │
│ API / 服务版本      Shell UID 2000 │
└───────────────────────────────────┘
[ 管理应用授权 / 无线调试激活 ]

激活与连接
┌ 无线调试                       › ┐
│ 电脑 ADB                       › │
└ 启动日志（存在时）             › ┘
必要说明

当前设备
┌ 型号、Android 版本             › ┐
共存摘要（检测到原版时）
```

- 只有真实服务连接且身份校验通过才使用绿色卡片。
- 未激活、连接中、失败使用对应文字与中性/错误语义；取消操作按实际激活状态展示。
- 在线主操作「管理应用授权」；离线主操作「无线调试激活」。连接期间禁用重复激活，保留取消。
- 无线、ADB、日志入口使用图标、标题、短摘要、箭头；没有日志时不伪造记录。
- 共存仅显示必要摘要，点击查看完整说明。

### 5.2 应用授权

- 页面标题右侧刷新；胶囊搜索框按应用名或包名搜索。
- 筛选为「全部、已允许、待询问、已拒绝」，选中使用淡蓝底和主色文字。
- 列表上方显示「Shell 权限」及真实应用数、已允许数。
- 应用合并为一张列表：真实图标、应用名、包名、右侧授权状态，点击打开管理弹层。
- 弹层显示应用名、包名、UID、当前状态、同 UID 共享授权说明；提供允许、拒绝、撤销并恢复询问。
- 保留独立的离线、加载、读取失败、无兼容应用、无匹配结果状态及相应入口。
- 授权变更期间禁用重复提交，以实际接口结果更新列表，失败保留真实状态与重试说明。
- 第三方权限请求继续使用经服务端校验的真实身份；取消/返回按拒绝处理。

### 5.3 设备诊断

- 标题右侧刷新。顶部设备卡显示真实厂商和型号；Android、API、安全补丁、ABI 使用两列信息布局，窄屏或大字体时自适应。
- 「内核与系统」显示完整 kernel release 摘要，详情弹层保留 kernel version、构建指纹、应用 UID 等完整信息。
- 「本地内核配置」提供系统文件选择入口，支持 `.config` / `.config.gz`；读取、失败、成功状态明确。
- 成功结果显示配置项统计、文本大小、压缩状态、完整 SHA-256；这些信息可以放在展开的结果或弹层中，不能丢失。
- 「运行能力」保持 Root、KernelSU、管理通道与设备支持等尚未验证状态；不能从格式有效或应用 UID 推断能力。
- 该页只读，无需激活权限服务。未读取到值时显示未提供，不填演示数值。

### 5.4 设置

- 产品图标、产品名、实际版本置顶。
- 「外观」：主题（跟随系统 / 浅色 / 深色）、动态配色。
- 主题选择使用居中选择对话框，三项在小屏和大字体下均可达；当前项同时用文字和主操作色表示。
- 「服务」：Shell 与 Root 说明、与原版 Shizuku 共存说明。
- 「关于」：实际版本/开发阶段、完整开源许可证。
- mock 中的「预览状态」和演示开关不进入原生应用。

## 6. 弹层与操作流程

- 弹层用于无线激活、电脑 ADB、日志、授权管理、完整系统信息和说明；同一时刻只显示当前操作所需内容。
- 无线激活保留「开启无线调试 → 配对 → 连接并激活」三个实际步骤；自动发现与手动输入均可达。
- 无线激活提供「通知栏配对」：用户主动启动前台搜索，在系统设置打开配对码窗口后，发现本机端口时通过高优先级通知提供六位码内联输入；无需在设置与应用之间往返。配对成功后提示返回应用连接并激活，不把配对成功显示为服务在线。
- 通知权限和本地网络权限按需申请；通知关闭时给出设置入口与手动配对入口。搜索有停止与超时，输入无效可重试；通知中的配对码不回显、不记录、不持久化或通过系统重投递恢复。
- 配对端口与连接端口分开标识；配对码仅留在当前操作内存，不记录、不恢复。
- ADB 命令使用运行时真实安装路径；支持选择与复制，不使用 mock 占位命令。
- 日志可滚动与复制，沿用敏感信息过滤。
- 错误保留在对应操作区域；取消、超时、失败不随后误报成功。
- 返回/关闭可操作；对话框和弹层不阻断必要的取消与拒绝路径。

## 7. 无障碍与适配

- 状态同时有文字，图标按钮有中文说明，装饰图标不重复朗读。
- 点击目标 ≥ 48dp；支持 TalkBack、键盘与系统返回。
- 字体缩放 200% 时可滚动、换行，主操作不被导航或键盘遮住。
- 深浅色均使用语义色；确保正文可读，不能仅凭 mock 中的小字截图判断原生可读性。
- 系统关闭动画时尊重其设置，不添加持续装饰动效。

## 8. 实现与验收

UI 只消费现有 ViewModel 状态与事件，不在 Composable 内实现新的高权限逻辑。UI 改造完成后执行：

```sh
bash ./gradlew :app:assembleDebug :app:assembleRelease lint testDebugUnitTest --no-daemon
```

工作目录为 `apps/android/`。构建与测试不能代替真机视觉验收。

- [ ] 四个页面与确认 mock 的层级、分组、导航一致。
- [ ] 已连接 / 未激活 / 连接中 / 失败与取消对应真实状态。
- [ ] 授权搜索、筛选、允许、拒绝、撤销及共享 UID 文案正确。
- [ ] 离线、读取中、错误、空列表、无结果状态互不混淆。
- [ ] 设备和配置详情完整；无 mock 数据、预览开关或假成功状态。
- [ ] 浅色、深色、动态色，手机、宽屏和 200% 字体均检查。
- [ ] 无线调试、ADB 命令、日志、授权请求、系统返回路径保持可用。

后续改变导航结构、主色体系或页面主操作时，先更新本规范并确认设计；普通排版修复与实际状态补全按本规范实施。
